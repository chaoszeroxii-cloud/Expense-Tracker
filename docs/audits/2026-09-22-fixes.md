## Dependencies ที่ยังต้องติดตาม

อัปเดต axios, bcrypt, TypeORM และ dependencies ที่เกี่ยวข้อง รวม lockfiles ทั้ง root/backend/frontend
นำ MulterModule ที่ไม่ได้ใช้ใน chat ออก; กำหนด overrides ที่จำเป็นต่อ dependency tree
ไม่ใช้ `npm audit fix --force`

| ขอบเขตที่ตรวจ | Critical | High | Moderate | Low |
|---|---:|---:|---:|---:|
| Backend production image (`--omit=dev`) | 0 | 0 | 6 | 0 |
| Frontend production lock (`--omit=dev`) | 0 | 0 | 2 | 0 |
| Root รวม development tools | 0 | 5 | 16 | 3 |

จำนวนคือ package entries ซึ่งรวมผลต่อเนื่องของ advisory เดียว ไม่ใช่จำนวน exploit
ที่พิสูจน์กับแอป หลักฐานแยกใน `2026-09-22-*-dependencies.json`

รายการ production ที่ยังเปิดอยู่เกี่ยวกับ Nest/SseStream, file-type, uuid และ React Router
ซึ่งมีเส้นทางแก้ผ่าน major upgrades ที่ยังไม่ได้ทำรอบนี้ จาก code review ปัจจุบัน chat
ส่ง SSE ด้วย event names คงที่และ JSON serialization ไม่ใช้ `@Sse`; ไม่มี FileTypeValidator
หรือ upload interceptor; frontend ไม่มี SSR hydration และ navigation ที่รับค่าจาก AI
ถูกจำกัดแล้ว ข้อสังเกตเหล่านี้ลดเส้นทางเข้าถึงบาง advisory แต่ไม่ได้ทำให้แพ็กเกจพ้น affected range

Development advisories ระดับ High ยังเกี่ยวข้องกับ Nest CLI/glob, picomatch, tmp และ Vite
จึงยังไม่ถือว่าการอัปเกรด dependencies เสร็จทั้งหมด ดู
[audit รวม dev](2026-09-22-all-dependencies.json) สำหรับ affected ranges และลิงก์ประกาศ

## Migration และการนำไปใช้

Migration ใหม่ `1785250000000-BillOccurrences` เพิ่มตารางและ backfill โดยไม่เขียนยอด
expenses, wallet balances หรือ user balances ใหม่ บิล active จะมีงวดตั้งแต่ start_month
จนเดือนปัจจุบัน; บิลที่หยุดไว้ก่อน migration เก็บงวดที่มีหลักฐาน payment เดิม เนื่องจาก
schema เก่าไม่มีวันที่หยุด จึงกู้ยอดค้างที่ไม่เคยบันทึกของบิลเหล่านั้นไม่ได้อย่างแน่นอน
จำนวนย้อนหลังใช้ template ที่มีอยู่ ผู้ใช้แก้หรือยกเลิกงวดค้างได้; ยอด expense ที่จ่ายจริงคงเดิม

รัน backend build แล้ว `npm run migration:run` ก่อนเปิด backend ใหม่ หรือใช้ `start:prod`
ที่รัน migrations ก่อน boot อยู่แล้ว ส่วน Docker production ต้องใช้ Compose 2.24.4+ และ
ตั้ง TRUST_PROXY_HOPS ตาม proxy topology ใน [README](../../README.md)
การ merge แบบ reset/override อ้างอิง [Docker Compose](https://docs.docker.com/reference/compose-file/merge/)
และขอบเขต trust proxy อ้างอิง [Express](https://expressjs.com/en/guide/behind-proxies/)

บัญชีที่เคยผูก social แบบเก่าไม่ได้ถูกลบหรือเปลี่ยนเป็นกลุ่ม การ recovery ผ่านอีเมลจะ
ปลด credentials เดิมและเปลี่ยนเป็น email/password; ต้องใช้ flow นี้เมื่อต้องการกู้บัญชีเดิม
การตรวจนี้ไม่ใช่การรับรองว่าไม่มีบัคหรือช่องโหว่อื่นในระบบ
